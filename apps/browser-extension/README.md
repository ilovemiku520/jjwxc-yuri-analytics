# Pixiv 元数据采集助手

这是项目自带的本地 Chrome/Edge Manifest V3 插件。它不负责登录，也不接收账号、密码、
Cookie、Token 或浏览器配置。只有用户点击“导出当前作品 JSON”时，插件才读取当前已经打开
的 Pixiv 作品页，并在本机生成一条最小化元数据。Pixiv 新版页面不再提供旧的预加载
标签；插件会在页面主线程观察该页面自己已经发出的单作品响应，并立即缩减为批准字段。
如果首次响应早于观察器加载，只有用户点击导出按钮后才会通过 Pixiv 当前网页使用的
非官方 `/ajax/illust/{work_id}` 接口，对当前作品 ID 发起一次同源、只读、禁止重定向的
回退请求。请求使用浏览器现有会话，但插件不读取 Cookie；响应在页面上下文中立即缩减，
只有批准字段可以返回弹窗。插件不会自动翻页、批量请求，也不会保存或转发原始响应。

## 本地安装

1. 在 Chrome/Edge 打开扩展管理页面并启用“开发者模式”。
2. 选择“加载已解压的扩展程序”，定位到本目录 `apps/browser-extension`。
3. 用户本人登录 Pixiv，打开一个能够正常查看的作品页。
4. 点击插件图标，选择“导出当前作品 JSON”。
5. 将生成的 `pyuri-pixiv-metadata-*.json` 拖到项目的
   `scripts/run-pyuri-browser-companion-import.cmd`。

远程 Windows 主机如果无法直接访问 Pixiv，可从项目根目录双击
`scripts/start-pixiv-browser.cmd`。该入口使用独立 Chrome 资料目录并自动加载本插件；
它只解决 Pixiv 页面连通性，不会替用户登录或触发采集。用户仍需本人在打开的 Chrome
窗口中完成登录并主动点击导出。

## 安全边界

- 插件优先不新增请求；仅在未捕获页面已有响应时，由一次人工导出点击触发当前作品的
  单次同源只读回退。它不自动翻页、不读取 Cookie，也没有后台采集服务。
- 插件只从当前作品页已有的预加载元数据中挑选 G0 批准字段。
- 图片、媒体 URL、描述正文、用户状态和原始页面载荷不会进入导出文件。
- `x_restrict` 只用于核对当前 G0 批准的全年龄/R-18/R-18G 范围，离线净化后不会保留。
- 输出仍是非正式候选数据；来源可见性审查通过前不得进入正式数据集。
- 数据仅限个人学习或研究使用，严禁商业用途或二次分发。

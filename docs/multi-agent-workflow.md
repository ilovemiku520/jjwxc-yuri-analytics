# 多 Agent 与低 Token 工作流

本文只约束项目内的协作方式，不改变项目目标、数据范围或任何安全门禁。

## 角色与边界

### 主 Agent

- 负责总体目标、阶段顺序、范围判断和最终整合。
- 负责 G0、源端点、身份/TLS、发布和真实采集等安全门禁；不能把 Fixture 或离线结果当作真实授权。
- 负责决定哪些任务可以并行，处理冲突，并对合并后的行为负责。
- 负责把外部网络、账号会话、凭据和用户批准保持在明确的边界内。

### `luna_worker`

- 固定用途：`gpt-5.6-luna`，推理强度 `max`。
- 只接收范围明确、边界清晰、可以独立完成的任务，例如一个模块的实现、一个报告格式的修正或一组针对性检查。
- 委派说明必须列出允许触及的文件、输入输出、禁止事项和完成判据。
- 不修改总体目标，不改变安全门禁，不自行扩大数据字段、网络范围或部署范围；遇到歧义时返回阻塞点。

### `explorer`

- 用于定位一个具体代码问题、配置问题或证据缺口。
- 先给出最小复现、相关文件和证据，再提出局部修复建议。
- 不负责跨模块重构、真实采集、账号登录或发布决策；发现跨边界影响时交回主 Agent。

## 委派协议

每个委派使用短而完整的任务卡：目标、允许文件、禁止范围、输入证据、输出物和验收条件。一个任务卡只解决一个独立问题；互不依赖的任务才并行，存在共享文件或顺序依赖时由主 Agent 串行整合。

子 Agent 完成后只返回：结果、改动文件、关键证据、已做的针对性检查和剩余阻塞。主 Agent 在整合前检查 diff、文件归属和安全边界，避免重复实现或重复读取。

## 减少 Token 的操作准则

- 使用精准的 `rg` 模式和已知路径；不要从项目根目录无目标地枚举或读取大量文件。
- 每个文件首次读取后记录要点；后续优先复用已读上下文，只有补充证据或遇到硬失败才重新读取。
- 先查看状态、报告和相关接口，再打开实现文件；不要为了确认同一事实反复扫描仓库。
- 优先让子 Agent 产出短证据摘要和小范围 diff；主 Agent 只接收与决策有关的日志片段。
- 使用 RTK 时仅将其作为终端输出压缩层，不改变命令语义、退出码、输入、文件或测试范围；RTK 失败时立即回退到原命令。
- 当前 `scripts/invoke-rtk.ps1` 只允许 `version`、`pytest`、`ruff`、`mypy`、`gain` 固定 profile，并要求项目本地二进制 SHA-256 完整性通过。
- RTK 必须保持遥测关闭、原始失败 tee 关闭、不安装全局 hook；共享会话只在确有需要时使用，临时跟踪数据库应在运行后删除。
- 非关键测试集中到模块完成或阶段出口统一执行；关键安全门禁、凭据隔离、网络禁用、字段白名单和失败关闭检查不能因节省 Token 而延后。

## 测试与审查节奏

模块开发期间只执行与当前改动直接相关的最小检查，并保存失败原因。模块完成后集中执行非关键回归、格式检查和类型检查，避免多个 Agent 重复跑同一套完整测试。

以下审查始终即时执行或保持阻塞，不能推迟到“全部模块完成”之后：

- 账号密码、Cookie、Token、会话和日志中的秘密不得进入代码、报告或数据库；
- 未经 G0、源端点合同和独立批准，不得访问真实 Pixiv 端点或启用真实采集；
- 允许字段、年龄分级、媒体/原始响应禁止项和限速必须由机器可验证门禁约束；
- 身份代理、TLS、CORS、发布批准和外部可达性必须保持 fail-closed；
- 任何网络、发布、数据库迁移或破坏性操作都必须有明确授权和可追踪证据。

## 当前 RTK 基线

本工作区的 `rtk_install.json` 与 `rtk_quality_smoke.json` 记录了 RTK 0.45.0 的本地安装和质量验证：安装范围为工作区本地，官方校验和与可执行文件完整性均已核对，遥测和原始失败 tee 均关闭，全局 hook 未安装，跟踪范围为临时质量会话，pytest、Ruff 和严格 mypy smoke 通过。本文不要求重新安装、升级或联网验证 RTK。

RTK 只能减少人类和 Agent 看到的输出量，不能减少必需的安全证据，也不能把失败结果隐藏为成功。需要完整原始输出时，直接使用原命令并保存其退出码与日志。
